# M5 — 日志轮转、七天保留与诊断安全验收

日期：2026-10-14
根目录：D:\DesktopCommanderRemote
分支：develop

## 实现内容

1. 保留 RollingFileLog 的按大小轮转，默认普通日志单文件 1 MB、最多 10 个轮转文件。
2. 详细日志使用独立配置 verboseLogMaxBytes（默认 5 MB）、verboseLogRetainedFiles（默认 4 个），默认为关闭。
3. 所有日志新增最长七天的保留期，并在日志对象创建时、运行中每 15 分钟、写入前到期检查时执行过期清理。活跃文件过期时在同一把锁中先轮转，再清理，避免并发写入导致竞态。
4. 清理范围限定为每份日志确切的文件名及其数字后缀，忽略无关文件（例如 *.tmp）和另一个类别的日志。
5. 使用 UTF-8 实际字节数计算文件大小；过大记录截断，防止中文/Unicode 内容突破单文件限制。统一记录转义 CR/LF 避免伪造日志行。
6. 日志写入、大小轮转、过期维护互斥；遇到锁定或不可访问文件时尽力维护，不导致托盘或 Remote 崩溃。
7. 减少普通日志写入未经处理的异常详细信息和堆栈；AgentLogPolicy 的白名单脱敏、SecretRedactor 和诊断报告的结构化、无原始日志政策继续保留。
8. 详细日志作为用户主动在 settings.json 启用的敏感模式，托盘新增显眼的启用标识及启动提示；诊断导出仍不包含其内容。
9. 保持旧配置文件向后兼容；旧用户已明确配置的普通日志数量继续以保存值为准，新配置采用 10 份的默认值。

## 保留限制、隐私和风险

- 保留七天表示最长保留时限；大小及数量达到上限时，较早的日志可能提前删除。过期活跃日志轮转和退休按保留边界处理，允许提前淘汰该文件中较新的部分记录。
- 原始详细日志可能包含远程工具输出或敏感文件内容，仅按用户显式选项创建；不自动开启，不纳入 Copy Diagnostics。
- 当前真实 Remote 仍由外部 npx 进程管理；未运行开发版托盘、未停止或接管 Remote，也未更改真实 HKCU Run。
- Windows GUI 弹出通知、真实磁盘写入失败、长期多日运行及安装器部署验收留待 M7。
- 未修改官方 Desktop Commander 凭据。
